Getting started

Install the addon, make sure your player can set off triggers, and build a proximity door that opens when the player walks up to it.

1. Install the addon

  1. Download the repository from GitHub (Code > Download ZIP) and unzip it.
  2. Copy the addons/godot_logic_nodes/ folder into your project's addons/ folder. Create addons/ if your project doesn't have one yet.
  3. In Godot, open Project > Project Settings > Plugins and tick Enable next to Godot Logic Nodes.

When the plugin is enabled:

  • A Logic I/O tab appears in the bottom panel, next to Output and Debugger.
  • Logic Nodes appear in the Add Child Node dialog. Search for "Logic".
  • The addon adds the input actions its nodes and demo player use to Project Settings > Input Map. Actions your project already has are left as they are.
ActionDefault keyUsed by
gln_interactEInteract Zone
gln_move_forwardWThe demo first-person player
gln_move_backSThe demo first-person player
gln_move_leftAThe demo first-person player
gln_move_rightDThe demo first-person player

Everything the addon names starts with gln_, so it won't clash with actions or groups already in your project.

2. Set up your player

Trigger Volumes and Interact Zones only react to physics bodies that are in a particular group. Out of the box that group is gln_player. Your player needs three things:

  1. A physics body. A CharacterBody3D with a CollisionShape3D is the usual choice.
  2. The right physics layer. The body must be on a layer the trigger's Collision Mask includes. Both default to layer 1, so this usually just works.
  3. The group. Select the player, open the Node > Groups tab next to the Inspector, type gln_player and click Add.
No player yet?

The addon ships with one. Drag addons/godot_logic_nodes/scripts/fpvPlayerController/FirstPersonController.tscn into your scene. It's already in the gln_player group: WASD to walk, mouse to look, Esc to free the mouse.

3. Build your first door

A proximity door opens when the player walks up to it and closes when they walk away. You need the door itself, one Move node to slide it, and one Trigger Volume to notice the player.

  1. Add a Move node. Select the node your level lives under, press Ctrl+A (Add Child Node), search for LogicMove and add it. New Logic Nodes appear in front of the editor camera, so look where you're pointing.
  2. Put the door under it. In the Scene tree, drag your door mesh onto the Move node so it becomes its child. Anything under a Move node moves with it. (Or leave the door where it is and pick it in the Move node's Target setting.)
  3. Set where it goes. In the Inspector, set Move Offset to how far the door should slide, for example (2, 0, 0) for 2 meters along X. A cyan line in the viewport shows the path. Leave Mode on Once.
  4. Add a Trigger Volume. Add a LogicTrigger node in front of the door. The transparent orange box is the area it watches. Change Size so the box covers the space in front of the door.
  5. Wire the trigger to the door. With the Trigger Volume selected, open the Logic I/O tab at the bottom. Click + Add Output twice and fill in the two rows:
My OutputTargetTarget Input
On Trigger Enterthe Move nodeGo To End
On Trigger Exitthe Move nodeGo To Start
  1. Press play. Walk into the box and the door slides open. Walk out and it slides shut.

Two thin wires now run from the Trigger Volume to the Move node in the viewport. Select either node and they turn thick and pulse toward the door, so you can see which way the signal flows.

Why Go To End and not Start?

Start means "head for the other end", and it's ignored while the door is still moving. If the player steps in and straight back out, the second Start is lost and the door stays open. Go To End and Go To Start always mean the same thing and turn the door around mid-move, so it always ends up where it should. Use them whenever a pair of events like enter/exit drives something.

Demo scenes

The addon includes scenes you can open, play and take apart:

SceneWhat's in it
scenes/Sandbox.tscnA labeled example of every node, plus working setups: a spinning fan, a moving light, a proximity door, an interact door, an elevator and a three-zone combination gate.
scenes/BenchmarkScene.tscnAn empty room with a door frame, two door halves and a player. Nothing is wired. It's the test task given to playtesters: make the door open and close.
scenes/StressTest.tscn93 Logic Nodes running at once, with an on-screen monitor. Used to check performance.

All paths are under addons/godot_logic_nodes/. The models/ folder also has ready-made pieces: a sliding door, a door frame, an interactable button and a feedback panel.
